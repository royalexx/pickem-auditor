# NBA WS4 independent evaluation v1

Research-only Phase 1/1.5 infrastructure under `PA-V25-MASTER-2026-11-09 / v1.1`.
This package does not collect data, predict minutes, fit NBA outcome models, update
production weights, change schedules, or approve releases. Python 3.11+;
`numpy` and `scipy` support optional calibration/distribution
research. Tests use `unittest`. No NUTS or GPU dependency.

## Reproduction

From repository root:

```bash
python -m unittest discover -s tests/nba_ws4 -v
python -m research.nba_ws4.report \
  --replay research/nba_ws4/evidence/original_replay_v2.json \
  --output-dir work/nba_ws4_new_scores
python -m research.nba_ws4 joint-fixture \
  --input research/nba_ws4/sample_joint_fixture.json \
  --output-dir work/nba_ws4_new_fixture
```

A directory can contain several immutable results. Reusing an exact existing
content-addressed result raises `FileExistsError`; no prior artifact is replaced.
`report.py` also uses exclusive file creation. Use a new output directory for a
rerun. The sample fixture is synthetic and carries no forecasting evidence.

To repeat raw-byte verification, mount the **original** Deepnote project files:

```bash
python -m research.nba_ws4.replay_original \
  --root /path/to/original/project \
  --output work/nba_ws4_new_raw_replay.json
python -m research.nba_ws4.audit_morning_original \
  --root /path/to/original/project \
  --output work/nba_ws4_new_morning.json
```

No current source fetch can substitute for these files. The committed compact
replay contains original probabilities and row hashes, independently parsed
outcomes, and source-file hashes. It allows scoring without accessing Deepnote;
revalidating the provider bytes requires the originals. Use the v2 receipt for analysis.

`original_attempt_ledger.json.gz` preserves all 1,314 original attempted sides,
including 602 rejected sides, in original order. Original identities that were
missing stay missing. NBA contract scoring uses only the 250 certified contracts;
this ledger includes both sports and must not be confused with 1,314 NBA contracts.
The separate morning cohort is diagnostic only, never added to this population.

## Canonical evaluation input v1

`python -m research.nba_ws4 evaluate --input INPUT.json --source-root SOURCE_ROOT
--output-dir NEW_DIRECTORY` consumes a JSON object containing `protocol` and a `candidates` array.
An example is generated by `tests/nba_ws4/test_evaluator.py::fixture`; its sources
are explicitly synthetic test bytes and are never market certification evidence.

`protocol` must contain:

| Field | Meaning |
|---|---|
| `registered_at` | Independently retained, pre-freeze protocol clock |
| `attempt_ids` | Complete precommitted attempted universe; omissions or duplicates fail integrity |
| `models` | Map from model ID to a single locked version |
| `stage` | `preliminary` or `finalized`; separate runs, never a best-stage choice |
| `calibration_version` | Locked calibration version, including explicit no-calibration |
| `reference` | One registered model/reference ID |
| `tail_thresholds` | Optional precommitted integer tail threshold by statistic |

Every candidate contains `attempt_id`, `contract`, `forecasts` keyed by model,
and optional `settlement`. A malformed candidate remains a rejected ledger entry.
A supplied but invalid model is quarantined with its exact reason; other valid
models may be scored descriptively, but the integrity gate fails.

Canonical contract identity is the SHA-256 of canonical JSON for exactly:

`sport, event_id, player_id, team_id, opponent_id, stat, line, period, overtime,
book, quote_id, quote_at, source_id, settlement_policy`.

The contract also carries `contract_id`, `event_start`, `slate_date`, `slate_id`
and `quote_receipt`. Period support currently fails closed outside full-game,
OT-inclusive NBA markets. Same player/line at another book or quote timestamp is
a distinct offered contract. Evaluate a locked offered universe; repeated offers
are correlated observations, never independent player outcomes. The historical
benchmark adapter preserves its original cross-book canonical line contracts
and does **not** rebrand them as individual executable offers.

Each forecast contains:

- Exact copied identity in `contract`, `contract_id`, `model_id`, `model_version`.
- `input_freeze_at`, `forecast_at`, `training_cutoff`, `fit_completed_at`,
  `original_archived_at`, `code_sha`, `model_artifact`.
- `calibration_version`, `calibration_labels_available_through`,
  `selection_labels_available_through`.
- `evidence_kind` (`prospective` or `historical_research`), `development_exposed`
  boolean, `stage`, `features`, `snapshot_sha256` over every other forecast field.
- Either explicit `abstention` with absent probabilities/PMF, or `probabilities`
  containing `over`, `under`, `push` unconditional masses. An optional complete
  integer PMF supports independent threshold and full-distribution checks.

Each source/model receipt contains `path`, byte `sha256`, `available_at`,
`retrieved_at`, and `clock_attestation="original_authenticated"`. Feature receipts
also contain `kind`, `team_id`, and for historical results `event_id`, `event_end`.
Quote receipt JSON contains its canonical `contract_id`. A WS1 adapter must verify
provider quote terms before issuing that normalized receipt. Settlement receipt
JSON must contain exactly the supplied normalized settlement fields, excluding
the receipt itself. The evaluator verifies equality to the source-bound payload.
A WS1 settlement adapter must independently derive those fields from official
provider bytes and retain its raw-to-normalized mapping, provider hash, event
identity, and final-status checks. The Nov10 adapter does this independently for
all NBA results. Arbitrary JSON furnished by a caller is not an official source.

Hashing verifies byte identity, not the truth of a timestamp. The upstream receipt
issuer must authenticate original retrieval/availability clocks and authority;
this package does not pretend a caller-provided string is a digital attestation.
Absent that evidence, keep the record rejected or historical diagnostic. Do not
retrocertify old forecasts to satisfy this stronger schema.

Settlement fields: `contract_id`, `team_id`, `period`, `overtime`, `policy`,
`status` (`final`, `void`, `pending`), `receipt`. Final settlements require
`participation="played"`, nonnegative integer `actual`, and `result` derived
exactly as `actual > line`, `< line`, or `== line`. Void requires `void_reason`
and `actual=null`. DNP is not zero; unresolved participation remains pending.
Settlement corrections append a new artifact referring to the superseded hash;
a freeze-selected settlement version must be specified before each scored run.

## Scoring and selection

Binary Brier/log loss use canonical P(Over | nonpush) and one actual Over target.
Push/void/pending stay in ledgers; they do not become Under or misses. Full
three-outcome Brier is **sum** squared error across Over/Under/Push (not the
binary scaling); void is external to the statistic distribution. Distribution
NLPD, CRPS, PIT, interval, zero and tail diagnostics use the entire predictive
law. Finite PMFs must contain all mass. Poisson CRPS uses the exact analytical
formula and scaled Bessel functions, never a renormalized truncated tail.

Calibration-in-the-large is observed minus predicted; signed Over residual is
predicted minus observed. Side-conditional confidence-minus-accuracy is a
separate statistic. `summary` reports confidence and hit rate so that difference
can be read directly. Scores at impossible outcomes retain `Infinity`, represented
as an explicit JSON string rather than capped or silently clipped.

Top-1/5/10 are per model and precommitted slate, ranked by maximum nonpush side
probability with contract-ID tie break; exact 0.5 is a tie abstention. Selection
occurs before outcomes are inspected, including void and unresolved cases.
Top-k is a confidence-ranking diagnostic, not a payout/EV strategy or approved
pick. Selected IDs, selected sides and resolved counts are separate. Full
eligible and market/stat slices are retained. Familiar per-contract chart columns
include all frozen controls and explicit unavailable WS2/WS3 columns.

Paired bootstrap resamples whole dates or whole date/game clusters, retaining
within-cluster matched losses and row-weighted loss differences. A single date
returns no date interval. Five-game sensitivity is explicitly descriptive and
cannot replace independent dates. Cross-date serial dependence requires a
preregistered block/HAC extension before confirmatory prospective inference.
Model agreement supplies no independent evidentiary votes.

## Calibration research

`python -m research.nba_ws4 calibration --input INPUT.json --output-dir NEW_DIRECTORY`
uses a JSON object containing `rows` and `policy`. Rows have `contract_id`, `event_id`, `date`,
`model`, `stat`, `p`, `y`, `is_oof`, `training_cutoff`, `forecast_at`, `event_start`,
`input_freeze_at`, `label_available_at`. Policy has `methods`, `registered_at`,
`model`, `stat`, `min_parametric`, `min_isotonic`, `min_dates`, `l2`.

Methods: none; regularized monotone Platt; regularized monotone Beta; isotonic.
Parametric shrinkage centers on identity calibration. Endpoints are clipped only
inside the calibrator's transform for numerical fitting, not in proper scoring.
Isotonic thresholds are configurable prerequisites and must be justified from
prior data. No method is fit to its target game, contemporaneous labels, in-sample
predictions, or a different statistic. OOF provenance is required, not inferred.

`prequential` holds whole calendar slates out, fits only earlier label-available
OOF rows, and outputs every method without choosing the best after outcomes.
`assess_untouched` requires registered improvement/noninferiority margins,
untouched/development-unexposed rows, and minimum dates/games; it assesses paired
Brier and log-loss intervals. Passing is research acceptance only. Multiplicity,
serial-dependence assumptions, coverage, tail behavior, computational budget and
independent release review remain mandatory external gates. The Nov10 exposed
one-date cohort supplies no eligible earlier calibration folds: no calibrated
improvement is claimed or manufactured.

## Current limitations and rollback

This is a research acceptance harness, not a source authority or model release.
WS2/WS3 implementations and genuine prospective predictions were not supplied.
General regulation/period markets and multivariate sampling are deliberately
blocked. Full distribution diagnostics cannot be reconstructed from threshold-only
legacy sidecars. Energy/Variogram require matched original scenarios; see
`JOINT_ENGINE_READINESS_V1.md`. Independent source replay is distinct from an
external review of this new audit code, which remains pending.

Rollback is to stop invoking this package and close its draft PR. If merged for
research later, revert the audit commit. No scheduled notebook, collector,
production model, Tier policy, WS1–WS3 module or historical archive is changed.

The full attempt ledger is losslessly compressed. Inspect its complete denominator with:

```bash
python -c "import gzip,json; r=json.load(gzip.open('research/nba_ws4/evidence/original_attempt_ledger.json.gz','rt')); print(len(r['attempts']))"
```

This prints 1314. Decoded and compressed hashes are both in `evidence/attempt_ledger_archive_receipt.json`.
