# Proposed C admission evidence checklist — not an accepted contract

Version a separate outcome admission contract before enabling real native mode.
The installed source trust population and independent review must bind exact
raw byte domains, authoritative event/player/team/stat/period identities,
listed versus eligible population, completion evidence, supported publication
and actual capture clocks. Unknown fields stay unknown and block applicable
settlement; never replace them with game-start/fetch dates. Explicitly retain
PLAYED, PLAYED_ZERO_MINUTES, DNP, PENDING and UNRESOLVED. DNP is not a void
without the applicable original product rule. Numeric zero proves neither.

Bind each settlement to the exact immutable forecast manifest and distribution,
original upstream source and fitted artifact hashes, reader/runtime code pins,
J same-draw scenario contract where applicable, and original offer only when
one exists. Missing offers prohibit offered-contract/payout claims; they need
not be invented for statistic-distribution infrastructure fixtures.

Store outcome records through a physically separate API/root. Each correction
must name its retained predecessor, same logical outcome and source evidence;
check monotonic supported release/capture chronology, reject orphan/backdated
corrections, preserve branches/conflicts as unresolved, and never overwrite
any outcome version or original forecast. Idempotence is not permission to
replace a logical forecast with different bytes. Report attempted and unique
items separately, with explicit terminal states and overlapping reason counts.

Independent acceptance must exercise these real public paths and tamper identity,
forecast bytes, offers, clocks, chain ancestry and storage. Controlled proper-score
and Over/Under/Push references verify evaluator arithmetic only. Historical
predictive evaluation remains a separately authorized, preregistered operation.
