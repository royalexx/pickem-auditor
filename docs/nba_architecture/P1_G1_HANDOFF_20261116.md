## Data and interfaces
- P1 consumes WS1 Record/Receipt normalized envelopes only; it introduces no collector. Source-byte SHA (when supplied), immutable WS1 record ID, receipts, date and identity are verified before feature generation.
- v2/nba_architecture/p1_history.py implements deterministic prior-game reconstruction, strict prior-local-date guards, date-aware membership-only candidate rosters, UNKNOWN legal eligibility/availability, DNP-versus-played-zero distinctions, made-threes and box-count constraints, immutable source receipts, and calls the authoritative G0 validate_pregame.
- Only the accepted v2.0.0 G0 pregame envelope is output. The schema version is nba-sojc-contract/2.0.0. Historical output is permanently HISTORICAL_RECONSTRUCTION_UNCERTIFIED. Retrospective retrieval is NOT authenticated original pregame capture.
- v2/nba_architecture/p1_vault.py is the segregated append-only official outcome vault. It preserves exact source bytes separately under SHA-256, versioned corrected records and DNP/unresolved/played-zero/void distinctions. Pregame builder never imports this vault; downstream C may read it only after input freeze and outside forecasting code.
- scripts/nba_p1_build_pregame.py runs offline and generates a frozen write-once envelope. It consumes one JSON file with exactly schedule, entries, ingested_at and original_bytes. The schedule supplies game_id, two canonical team_ids, event_start_at, input_freeze_at, forecast_at, training_cutoff_at, decision_local_date. Entries use WS1 Record and Receipt asdict values. Original_bytes maps receipt IDs to safe relative paths under optional --source-root; missing originals stay unverified. No clocks are guessed.
- API: build_historical_pregame(...), validate_ws1_envelope(...), freeze_historical(...), OfficialOutcomeVault(...).latest/append/records.
- tests/nba_architecture/test_p1_history.py supplies synthetic fixtures and adversarial cases covering G0 conformance, chronology, SHA/correction protection, identities, shooting accounting, DNP, reproducibility and immutability.
- Historical prior-game candidate rosters are not verified trades or active lists. A target-game box-score cannot supply its own roster/rotations. Missing eligibility means UNKNOWN, never eligible by default.
- Full population shard SHA cannot be treated as an as-of prior-game source because it can contain games after the forecast. P1 binds each feature to the selected normalized WS1 record and retains the original-provider receipt separately. SHA match proves integrity of bytes supplied, not source authenticity.
